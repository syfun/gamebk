# 手机端存档备份与恢复交互优化

Status: ready-for-agent

## 问题

用手机打开 GameBK 时，用户要先点「刷新」才能看到已配置的游戏。窄屏下，游戏列表和备份历史仍需要横向滚动，用户要来回滑动才能核对一条记录的全部信息。备份需要经过命名表单，恢复则会在点击后立即提交整目录替换。

用户需要在手机上快速完成已配置游戏的备份和恢复，并在恢复或删除前看清操作对象和后果。

## 方案

打开 GameBK 后自动加载游戏列表。手机端用纵向卡片展示游戏和备份历史。进入游戏详情即可在首屏一键备份、按自定义名称备份，或确认后恢复最新备份。查看历史时可从对应卡片发起恢复。

配置、完整路径和删除操作通过相应页面或备份卡片的「更多」访问。恢复和删除各确认一次。手机卡片与桌面表格共用确认、处理中和结果反馈。

## 实现决策

- 继续使用游戏列表与游戏详情两个网页入口，由现有 Gin 服务提供页面和 API。小屏使用单列卡片，桌面使用现有表格布局。游戏列表进入时自动加载。
- 将手机端的新建、刷新和健康检查放在列表页的「更多」。在游戏详情的「更多」放置编辑配置和删除全部备份，在备份卡片的「更多」放置完整路径和删除单条备份。列表空态提供新建入口。
- 详情首屏的备份及恢复入口随内容滚动。卡片、菜单和确认控件使用适合触控的点击区域。较长的名称和路径在各自的查看区域内换行。
- 「立即备份」将名称字段提交为 `null`，由服务端按其本地时间生成名称。自定义入口使用填写的名称，留空时走同一默认命名规则。成功后展示服务端返回的实际备份并重新加载历史。
- 成功响应中的空记录按空态展示。读取失败提供错误和重试入口。游戏详情按照备份历史的当前状态控制「恢复最新」是否可用。
- 「恢复最新」在打开确认前读取该游戏的备份记录，按创建时间选择最新备份。历史恢复直接选择当前条目。两者都在确认时显示游戏、备份名称、创建时间和整目录替换的提示，提交时使用该确认对象的备份 ID。
- 单条和批量删除都在提交前展示一次确认，文案分别说明该备份和该游戏的全部备份。删除成功后重新加载历史。批量删除结果采用服务端响应中的删除数量。
- 游戏配置通过现有接口保存。成功后更新界面上的游戏名称与目录信息，失败时保留已填内容。
- 同一页面同时只处理一个修改当前游戏数据的请求。处理中显示动作提示并禁用相应提交入口，请求结束后恢复交互。连接中断且结果无法判断时提示刷新相关记录。

## 测试决策

- 以现有网页为统一操作入口。通过浏览器从游戏列表进入详情并执行配置、备份、恢复和删除。每组用例使用独立的临时数据库、存档目录和备份目录。
- 断言用户可见的内容、可用的操作入口、备份记录，以及临时目录里的文件结构和内容。用手机竖屏的代表性宽度（例如 360 和 430 CSS 像素）覆盖长名称和长路径，用桌面宽屏覆盖表格和共用确认反馈。
- 验证列表自动加载、空态、失败重试和配置菜单。验证手机列表与历史可在纵向滚动中操作，详情首屏的按钮随页面滚动。
- 验证立即备份的默认名称、自定义名称和卡片历史更新。延迟一次浏览器请求的响应，连续触发同一个按钮，核对最终只创建一份备份。
- 准备两份文件内容不同的备份。验证每种恢复的确认信息、取消时的目录快照，以及确认后存档目录与所选备份的内容一致。在确认期间用另一个浏览器页面创建更新的备份，核对实际恢复的仍是已展示的版本。
- 在确认期间从另一浏览器页面删除目标，验证原页面收到失败反馈并能刷新历史。分别覆盖单条删除与批量删除的一次确认、更新后的列表、实际移除的文件和服务端返回的删除数量。
- 使用浏览器模拟读取失败、响应延迟和连接中断，核对等待期间的按钮状态、错误反馈和刷新后的记录。
- 复用 `make build` 构建用于端到端验收的本地服务。项目已有的 `make build-win` 提供 Windows 构建验证，网页端到端用例从本规格的场景起步。
